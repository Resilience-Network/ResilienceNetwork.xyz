// ONBOARDING

From clone to consensus.

A producing four-validator network on your machine, from a clean checkout. Everything below is the short path; the canonical guides in the repository own the details and stay current.

Prerequisites

Step 00
  • Go — the version pinned in go.mod
  • Rust — CI pins rustc/cargo 1.88.0, plus a C compiler/linker and Cargo dependencies (the native Orchard cryptography builds through cgo)
  • Python 3 — development scripts and reference checks
// BUILD MODES MATTER

CGO_ENABLED=0 go build ./... compiles without native Orchard support; such binaries cannot process shielded activity. Every shipped artifact instead builds cgo-enabled with the native library statically linked — use make build and you get the real thing.

Build

Step 01
CLONE & BUILDSHELL
git clone https://github.com/Resilience-Network/Chain.git
cd Chain
make build               # native crypto + all binaries

./build/resilienced --help
./build/resilience-cli --help

make build RUNS make build-crypto (RUST ARCHIVE INTO build/lib/) THEN BUILDS ALL GO BINARIES

The build produces the daemon (resilienced), the CLI, key generation, a benchmark harness, a faucet, a block explorer, and genesis ceremony tooling.

Run a Local Network

Step 02
FOUR-VALIDATOR LOCALNETSHELL
bash scripts/localnet.sh start
bash scripts/localnet.sh status
bash scripts/localnet.sh stop

The script brings up a producing four-validator development network with matching keys and genesis. A daemon launched alone, without a matching validator set, will not create a producing network by itself. A healthy HTTP listener alone does not establish advancing consensus — repeat a block query and compare nodes when in doubt.

Connect

Step 03

The node serves JSON-RPC over HTTP and WebSocket on loopback (defaults: 127.0.0.1:8545 HTTP, 127.0.0.1:8546 WebSocket) with 66 registered methods across the web3, net, eth and rsc namespaces. The eth_* surface means existing Ethereum tooling works unmodified; the rsc_* surface exposes sessions, staking, names, recovery and shielded state.

  • Wallet integration — transaction formats, session composition and the experimental acknowledgment: wallet integration guide
  • CLI — account, transaction and admin operations: CLI usage
  • RPC contracts — parameter and result semantics per method: RPC reference and the registered inventory
  • Configuration — every field and its semantics: configuration reference
// SHIELDED ACTIVITY — EXPERIMENTAL ACKNOWLEDGMENT

Shielded transfers require the native build and an explicit experimental acknowledgment, and wallet scanning assumes a trusted RPC. Treat the privacy layer as a research preview, not a product. Current limits are tracked on the Status page.
