Load Qualification

Campaign 2026-09-20 · Issue #226

The first published load numbers for the chain, run on 2026-09-20 against origin/main @ 808d68b: offered-load sweeps with mixed traffic (80% transfers / 20% SSTORE calls) across four RPC endpoints and many clients, on a native cgo build with a four-validator network.

Offered Load Outcome Detail
20 TPS · 30 min Stable 35,984 / 35,984 included · p50 1.5s · p95 3.8s — highest stable point
50 TPS · 60s Stable Full inclusion · p50 ~1.5s · p95 ~4.3s
50 TPS · 32 min Unstable Healthy ~5 min, then multi-minute halts (62/42/133/112s+ gaps)
75 TPS · 45s Degraded Sporadic liveness: 5 blocks in 65s · 31% included
100–200 TPS Frozen ~600–800 included in the first 6–12s, then multi-minute finality halt
500 TPS · 30s Frozen Zero blocks · 0 / 3,000 included
Single client · stock bench Capped ~10 TPS admitted by the per-IP submit limiter · 0 included (unfunded keys)

Findings

  • The first bottleneck at every saturation point is consensus liveness (finality halts with the "all consensus rounds exhausted" signature, tracked in issue #210) — not execution, RPC throughput, mempool capacity, or disk.
  • The cliff is time-at-load, not just rate: 100+ TPS stalls in seconds; 50 TPS holds ~5 minutes then halts; 20 TPS holds 30 minutes clean.
  • The gas ceiling (~300 TPS for 50k-gas transfers at 30M gas / 2s slots) and the 4096-transaction mempool cap were never reached — liveness binds first.
  • Testnet sizing implication: plan ≤20 TPS sustained until the liveness failure is root-caused and fixed.
// ENVIRONMENT CAVEAT — LOWER BOUNDS

The campaign container was CPU-contended by other tenants (system load ~12–15 on 10 vCPUs). Latency tails and the exact position of the liveness cliff are therefore lower bounds under contention; a quiet host does the same or better, never worse for these mechanisms.

Verification Methodology

How the claims are made

Differential EVM testing

The EVM engine is continuously differentially tested against a reference implementation: the same transaction, replayed into both engines, must produce identical state transitions, gas and receipts. Divergences are bugs by definition, and get their own harness lanes.

Live-network user stories

Sixty-nine executable story files drive a real four-validator network end-to-end — session delegation, shielded pool invariants, staking boundaries, RPC integrity, offline guards — including dedicated byzantine-behavior and story-gate suites that must pass on every change.

Determinism and races

A determinism lint, race-enabled test runs, and a fresh-chain story harness back the deterministic-execution guarantee: same inputs, same state root, every time, on every validator.

Independent models and vectors

The reference/ tree keeps independent models, formal artifacts and test vectors — including the native Rust cryptography — separate from the Go implementation, so conformance is checked against something other than the code that produced it.
